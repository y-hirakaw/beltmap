# beltmap のクラウドルーチン取得

beltmap は単体バイナリであり、claude.ai の認証情報を持たない。持たせない方針でもある。
一方このセッションは既に認証済みなので、**取得だけを代行する。**

## この skill がやらないこと

**判断を一切しない。**API の応答をそのまま書き写すだけである。

要約したり、整形したり、不要そうなフィールドを削ったりしてはならない。beltmap 側は
これを決定論的な実測値として扱い、確信度 `confirmed` で地図に描く。ここで手を加えると
その前提が崩れる。**推測が要る部分は `beltmap-enrich` skill の担当であって、ここではない。**

## 手順

### 1. 一覧を取得する

`RemoteTrigger` ツールを `action: "list"` で呼ぶ。これは claude.ai の
`GET /v1/code/triggers` を叩き、OAuth トークンはツール内部で付与される。

`RemoteTrigger` が使えない場合は、その旨をユーザーに伝えて終わる。**代わりに
`claude -p` を使ってはならない。**

`create` / `update` / `run` は**呼ばない。**beltmap は読み取り専用のツールである。

### 2. そのまま書き出す

`.beltmap/routines.json` に、この形で書く。

```json
{
  "version": 1,
  "fetched_at": "2026-07-26T12:34:56Z",
  "response": { ここに API の応答をそのまま入れる }
}
```

- `response` は API が返した JSON をそのまま入れる。キーの削除・並べ替え・値の整形をしない
- `fetched_at` は取得時刻(UTC, RFC3339)。beltmap はこれで情報の古さを表示する
- コードフェンスで包まない。JSON ファイルとして書く

`.beltmap/` が無ければ作る。既存のファイルは上書きしてよい(毎回の取得結果で置き換わる)。

### 3. 結果を伝える

取得したルーチンの件数と、その名前を伝える。そのあと `beltmap scan` を再実行すると
地図に反映される、と案内する。

取得できたルーチンが0件だった場合は、それが正しい結果である可能性(クラウドルーチンを
使っていない)と、アカウントが違う可能性の両方を伝える。**0件を「失敗」と決めつけない。**
